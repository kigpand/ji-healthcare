# 개발

1. README와 관련 화면→훅→스키마→서비스 흐름을 읽는다. Git 사용 가능 시 status와 diff를 확인한다.
2. 요청을 관찰 가능한 성공 조건으로 바꾼다. 예: 카테고리 변경 후 저장·재진입해도 선택값이 유지된다.
3. 여러 파일·데이터 변경은 짧은 단계별 계획을 제시한다. 동작이 불명확하면 의존하지 않는 조사를 먼저 진행한다.
4. 버그는 재현 테스트를 작성하고 실패를 확인한다. 요구 동작을 구현하는 최소 변경을 한다.
5. `npm run check`를 실행한다. 의존성/네이티브/라우팅 변경은 `npm run build:check`도 실행한다.
6. 화면·알림·DB 변경은 testing.md의 해당 기기 시나리오를 검증하고 실행 환경을 기록한다.
7. diff에서 범위 밖 변경과 새로 생긴 미사용 코드를 확인하고 결과를 보고한다.

DB 호출을 화면에 추가하지 않는다. 시간 기반 동작은 실제 경과 시간과 백그라운드 복귀를 고려한다. 숫자 정규화는 입력값의 의미를 바꾸지 않아야 한다. Expo SDK 호환 버전을 사용하고 의존성 변경 시 package-lock.json을 함께 갱신한다.

완료: 요구사항 충족, 관련 회귀 검사 통과, 검사 실패·미실행 사유 공개. 기존 실패를 숨기기 위한 설정 변경은 완료로 인정하지 않는다.
