# 테스트

## 자동 검사

```sh
npm run check
npm run test:ci
npm run build:check
```

`check`는 린트→타입→Jest 순서로 실패 시 중단한다. `test:ci`는 커버리지를 생성한다. `build:check`는 모바일 JS 번들 검사이며 Xcode/Gradle/실기기 테스트가 아니다.

테스트는 tests/에 둔다. 정상·경계·실패 동작을 검증하고 내부 구현이나 스냅샷을 그대로 복제하지 않는다. 현재 날짜가 필요한 테스트는 시간을 고정하고 복원한다. DB·알림 모킹은 호출 계약만 검증하므로 실제 모듈 호환성을 검증했다고 주장하지 않는다.

## 기기 시나리오

테스트 전용 설치/데이터를 사용한다. 사용자의 실제 운동 기록을 초기화하지 않는다. 다음 표의 관련 항목을 플랫폼, 앱 버전/커밋, 기대값, 실제값, 로그/스크린샷과 함께 기록한다.

| 상황 | 기대 결과 |
| --- | --- |
| 첫 실행→카테고리→루틴 등록→재실행 | 데이터 유지, 중복 생성 없음 |
| 카테고리 A→B 편집→저장→재진입 | B 유지; 현재 알려진 결함 |
| 무게 2.5 입력/붙여넣기→저장 | 2.5 유지; 자동 회귀 테스트 추가, 기기 검증 필요 |
| 세트 완료→60초 휴식→잠금 70초→복귀 | 남은 시간 0, 다음 세트 시작 가능; 자동 회귀 테스트 추가, 기기 검증 필요 |
| 마지막 세트 완료 | 기록 정확히 1건, 저장 중 중복 동작 없음 |
| 알림 권한 거부 | 운동 진행 가능, 처리되지 않은 오류 없음 |
| 저장 실패→재시도 | 실패 표시, 연속 재시도·성공 후 재시도 중복 방지; 자동 회귀 테스트 추가, 기기 검증 필요 |
| 기록 저장 대기·진행 중 홈/뒤로가기 | 화면 이탈 차단; 자동 회귀 테스트 추가, 기기 검증 필요 |
| 기록 저장 실패 후 홈/뒤로가기 | 머무르기 또는 기록 포기 확인 후 이탈; 자동 회귀 테스트 추가, 기기 검증 필요 |
| 사용 중 카테고리 삭제 | 참조 데이터 보존, 이유 표시 |
| 자정 전후 기록·기간 필터 | 로컬 날짜 기준 홈 통계·기간별 기록 갱신; 월말·연말 자동 회귀 테스트 추가, 기기 검증 필요 |
| 날짜가 바뀐 후 앱 복귀 | 현재 날짜로 즉시 갱신하고 다음 자정 갱신 예약; 자동 회귀 테스트 추가, 기기 검증 필요 |
| 기존 설치에 새 버전 설치 | 마이그레이션 성공, 기존 기록 유지 |

알려진 문제는 통과 처리하지 않는다. 수정 작업에서는 이 시나리오를 자동 회귀 테스트로 전환한다. 새 기기 검증 결과는 릴리스 기록에 첨부한다.

완료 보고: 검사 명령·통과/실패 수, 재현 단계, 모킹 범위, 실행하지 못한 기기 검사. 실패하면 기대값을 약화하지 말고 원인을 개발 작업으로 돌려보낸다.
