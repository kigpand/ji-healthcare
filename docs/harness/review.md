# 리뷰

리뷰 요청은 기본적으로 읽기 전용이다. 수정 요청이 함께 있을 때만 코드를 변경한다.

## 리뷰어 독립성

사용자가 별도 방식을 지정하지 않으면 리뷰는 제3자 관점으로 진행한다.

- 가능한 경우 구현을 담당하지 않은 별도 리뷰 에이전트가 검토한다.
- 리뷰 에이전트에는 요구사항, 비교 기준, 변경 코드, 관련 테스트와 실행 결과만 전달한다.
- 구현 과정의 대화, 작성자의 자체 평가, 의도한 정답이나 예상 발견 사항은 전달하지 않는다.
- 리뷰 결과는 주 에이전트가 파일·줄·재현 조건을 다시 확인한 뒤 사용자에게 전달한다. 근거가 확인되지 않은 지적은 발견 사항에 포함하지 않는다.
- 별도 리뷰 에이전트를 사용할 수 없으면 같은 에이전트가 리뷰한다는 사실과 작성 맥락을 알고 있다는 한계를 결과에 명시한다.

사용자가 구현 의도까지 고려한 리뷰를 요청하면 현재 에이전트가 요구사항 충족 여부와 설계 판단을 함께 검토할 수 있다. 어떤 방식을 사용했는지 리뷰 결과에 밝힌다.

1. PR/브랜치/작업 트리 중 비교 대상을 확인한다. 전체 프로젝트 리뷰라면 변경분만으로 범위를 축소하지 않는다.
2. 호출자와 데이터 흐름까지 읽는다. 단편적인 스타일 선호를 결함으로 보고하지 않는다.
3. 정확성, 기록 손실·중복 저장, 비동기 경쟁, 캐시 갱신, 마이그레이션, 권한 거부, 백그라운드 복귀를 우선 확인한다.
4. `npm run check` 및 필요한 재현을 실행한다. 통과해도 동작상 안전을 단정하지 않는다.
5. 발견 사항마다 파일/줄, 발생 조건, 실제 영향, 수정 방향을 제공한다. 확인 사실과 추정을 구분한다.

우선순위: P0 즉시 중단할 광범위한 손상, P1 핵심 기능 실패·데이터 손실, P2 일반적인 기능 결함, P3 낮은 영향의 개선.

출력은 발견 사항부터 시작하고 검사 결과·미검증 범위를 덧붙인다. 발견 사항이 없으면 없다고 명시한다. 개발자의 완료 보고만으로 승인하지 않는다. 알려진 문제는 신규 회귀와 구분하며 배포 영향도 함께 판단한다.
